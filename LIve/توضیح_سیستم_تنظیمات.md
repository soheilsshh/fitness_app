# 📋 توضیح کامل سیستم مدیریت تنظیمات

## 🎯 هدف

این سیستم امکان تغییر تنظیمات سیستم را از طریق پنل ادمین فراهم می‌کند، بدون نیاز به دسترسی به فایل‌های سرور یا restart دستی.

---

## 🏗️ معماری سیستم

### 1. **ذخیره‌سازی (Storage)**

#### دیتابیس (اولویت اول)
- تنظیمات در جدول `system_configs` ذخیره می‌شوند
- هر تنظیم به صورت `key-value` ذخیره می‌شود
- مثال: `webinar.start_hour = "20"`

#### فایل Config (Fallback)
- اگر تنظیمی در دیتابیس نباشد، از `config.yaml` استفاده می‌شود
- این باعث می‌شود که تنظیمات اولیه همیشه موجود باشند

### 2. **جریان کار (Flow)**

```
┌─────────────────┐
│  Admin Panel    │
│  (Frontend)     │
└────────┬────────┘
         │ PUT /api/admin/config/webinar
         ▼
┌─────────────────┐
│  API Controller │
│  (Backend)      │
└────────┬────────┘
         │ Save to Database
         ▼
┌─────────────────┐
│   Database      │
│  (MySQL)        │
└─────────────────┘

┌─────────────────┐
│  Server Startup │
└────────┬────────┘
         │ Load Config
         ▼
┌─────────────────┐
│  Merge Config   │
│  DB + File      │
└────────┬────────┘
         │ Use Merged Config
         ▼
┌─────────────────┐
│  Services &     │
│  Scheduler      │
└─────────────────┘
```

## 📊 بخش‌های تنظیمات

### 1. **زمان‌بندی وبینار (Webinar Schedule)**

**تنظیمات:**
- `start_hour`: ساعت شروع (0-23)
- `start_minute`: دقیقه شروع (0-59)
- `end_hour`: ساعت پایان (0-23)
- `duration_minutes`: مدت زمان (محاسبه خودکار)

**استفاده:**
- Scheduler از این تنظیمات برای زمان‌بندی روزانه استفاده می‌کند
- استریم در زمان دقیق شروع وبینار شروع می‌شود
- بعد از restart، تنظیمات از دیتابیس خوانده می‌شوند

**مثال:**
```
start_hour: 20
start_minute: 0
end_hour: 22
→ وبینار هر روز ساعت 20:00 شروع و 22:00 تمام می‌شود
```

---

### 2. **Melipayamak (SMS Service)**

**تنظیمات:**
- `username`: نام کاربری Melipayamak
- `api_key`: کلید API
- `body_id_welcome`: کد پیام خوش‌آمدگویی
- `body_id_welcome_next_day`: کد پیام خوش‌آمدگویی روز بعد
- `body_id_reminder_2pm`: کد پیام یادآوری ساعت 14:00
- `body_id_reminder_30min`: کد پیام یادآوری 30 دقیقه قبل
- `enabled`: فعال/غیرفعال

**استفاده:**
- برای ارسال پیامک‌های خودکار
- بعد از restart، تنظیمات جدید اعمال می‌شوند

---

### 3. **Avanak (Voice Call Service)**

**تنظیمات:**
- `token`: توکن احراز هویت
- `message_id`: کد فایل صوتی
- `base_url`: آدرس API
- `enabled`: فعال/غیرفعال

**استفاده:**
- برای ارسال تماس صوتی خودکار
- بعد از restart، تنظیمات جدید اعمال می‌شوند

## 🔄 چرخه زندگی تنظیمات

### 1. **تغییر تنظیمات (Admin Panel)**

```
کاربر → Admin Panel → تغییر تنظیمات → کلیک "ذخیره"
  ↓
API Call: PUT /api/admin/config/webinar
  ↓
Controller: UpdateWebinarConfig()
  ↓
Database: INSERT/UPDATE system_configs
  ↓
Response: ✅ تنظیمات ذخیره شد
```

### 2. **Restart سرور**

```
Server Start
  ↓
Load config.yaml (default values)
  ↓
Load from Database (override values)
  ↓
Merge Config (DB values override file values)
  ↓
Initialize Services with Merged Config
  ↓
Start Scheduler with Merged Config
```

### 3. **استفاده در Runtime**

```
Scheduler Job (20:00)
  ↓
Read Config from Merged Config (not DB directly)
  ↓
Use Config for Stream Start Time
  ↓
Start Streaming at Correct Time
```

## 💾 ذخیره‌سازی در دیتابیس

### ساختار جدول `system_configs`

```sql
CREATE TABLE system_configs (
  id INT PRIMARY KEY AUTO_INCREMENT,
  key VARCHAR(191) UNIQUE,
  value TEXT,
  created_at TIMESTAMP,
  updated_at TIMESTAMP
);
```

## 🔐 امنیت

### 1. **Authentication**
- فقط کاربران admin می‌توانند تنظیمات را تغییر دهند
- JWT token برای احراز هویت

### 2. **Validation**
- بررسی محدوده‌های عددی (0-23 برای ساعت، 0-59 برای دقیقه)
- بررسی صحت فرمت داده‌ها

### 3. **Sensitive Data**
- API Key و Token به صورت password input نمایش داده می‌شوند
- در دیتابیس به صورت plain text ذخیره می‌شوند (نیاز به encryption در آینده)

## 📝 نکات مهم

### 1. **Restart لازم است**
- تغییرات Melipayamak و Avanak نیاز به restart دارند
- تغییرات Webinar از روز بعد اعمال می‌شوند (scheduler در 00:00 اجرا می‌شود)

### 2. **Fallback به Config File**
- اگر تنظیمی در دیتابیس نباشد، از `config.yaml` استفاده می‌شود
- این باعث می‌شود که تنظیمات اولیه همیشه موجود باشند

### 3. **Merge Strategy**
- دیتابیس اولویت دارد
- اگر در دیتابیس موجود باشد، از دیتابیس استفاده می‌شود
- در غیر این صورت، از `config.yaml` استفاده می‌شود

## 🚀 بهبودهای آینده

1. **Hot Reload**: اعمال تغییرات بدون restart
2. **Encryption**: رمزگذاری API Key و Token

4. **Validation**: اعتبارسنجی پیشرفته‌تر
5. **Notifications**: اطلاع‌رسانی بعد از تغییر تنظیمات
