# 🔧 رفع مشکل زمان شروع استریم و شروع از وسط ویدیو

## 🐛 مشکلات شناسایی شده

### مشکل ۱: استریم در زمان اشتباه شروع می‌شد (20:10 به جای 20:00)

**علت:**
- در `main.go` استریم بلافاصله شروع می‌شد (برای ایجاد channel)
- `StartFilePublisher` فقط لاگ می‌زد که باید صبر کند اما **واقعاً صبر نمی‌کرد**
- scheduler در 20:00 استریم را دوباره شروع می‌کرد، اما اگر استریم قبلاً در حال اجرا بود، تداخل ایجاد می‌شد

### مشکل ۲: ویدیو از وسط شروع می‌شد (از دقیقه 15)

**علت:**
- ویدیو همیشه از ابتدا شروع نمی‌شد
- اگر استریم قبلی در حال اجرا بود، ممکن بود از ادامه شروع شود
- فایل ویدیو ممکن بود از آخرین موقعیت خوانده شود

## ✅ راه‌حل‌های اعمال شده

### ۱. اضافه شدن Wait واقعی در `StartFilePublisher`

**قبل:**
```go
if waitDuration > 0 {
    log.Printf("Starting stream now (webinar starts at %s in %v)...", ...)
    // هیچ Sleep نمی‌شد! فقط لاگ می‌زد
}
```

**بعد:**
```go
if waitDuration > 0 {
    log.Printf("⏳ Waiting %v until webinar starts at %s...", waitDuration, ...)
    time.Sleep(waitDuration)  // واقعاً صبر می‌کند!
    log.Printf("✅ Wait completed. Starting stream now at %s", ...)
}
```

**نتیجه:** استریم دقیقاً در زمان شروع وبینار شروع می‌شود.

### ۲. اطمینان از شروع ویدیو از ابتدا (time 0)

**تغییرات:**
- فایل همیشه به صورت fresh باز می‌شود
- `firstPacketTime` درست تنظیم می‌شود
- لاگ اضافه شد برای اطمینان از شروع از ابتدا

**کد:**
```go
log.Printf("🎬 Starting real-time stream for %s from BEGINNING (time 0)...", filePath)
if firstPacketTime == -1 {
    firstPacketTime = pkt.Time
    log.Printf("🎬 First packet time: %v (starting from beginning)", firstPacketTime)
}
```

**نتیجه:** ویدیو همیشه از ابتدا شروع می‌شود.

### ۳. جلوگیری از شروع چند استریم همزمان

**اضافه شده:**
```go
var (
    streamRunning   bool
    streamMutex     sync.Mutex
    currentStreamEndTime time.Time
)
```

**قبل از شروع:**
```go
streamMutex.Lock()
if streamRunning {
    streamMutex.Unlock()
    log.Printf("⚠️  Stream is already running. Skipping new stream request.")
    return
}
streamRunning = true
streamMutex.Unlock()
```

**بعد از پایان:**
```go
streamMutex.Lock()
streamRunning = false
streamMutex.Unlock()
```

**نتیجه:** فقط یک استریم در هر زمان می‌تواند اجرا شود.

## 🔍 بررسی فنی

### ۱. Timing Logic

**`StartFilePublisher` اکنون:**
1. زمان فعلی را با زمان شروع وبینار مقایسه می‌کند
2. اگر زمان شروع در آینده است، **واقعاً صبر می‌کند** (`time.Sleep`)
3. اگر زمان شروع گذشته است (بیش از 5 دقیقه)، استریم را شروع نمی‌کند
4. اگر زمان شروع نزدیک است (کمتر از 5 دقیقه)، بلافاصله شروع می‌کند

### ۲. Video Playback Logic

**اطمینان از شروع از ابتدا:**
1. فایل همیشه به صورت fresh باز می‌شود
2. `firstPacketTime` از اولین packet خوانده می‌شود
3. همه محاسبات timing از `firstPacketTime` انجام می‌شود
4. لاگ اضافه شده برای debug

### ۳. Concurrency Control

**جلوگیری از تداخل:**
1. از `sync.Mutex` برای thread-safe access استفاده می‌شود
2. قبل از شروع، بررسی می‌شود که آیا استریم در حال اجرا است
3. بعد از پایان، flag reset می‌شود
